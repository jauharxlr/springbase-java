Basic CRUD (PostgREST style)

SpringBase follows the PostgREST convention for RESTful operations.

Read All Rows

GET /rest/v1/tasks

Create Row

POST /rest/v1/tasks
{ "title": "Finish Documentation", "status": "pending" }

Advanced Filtering

Use URL parameters to filter your results with powerful operators.

Equals

?id=eq.123

Greater Than

?age=gt.18

Like (Pattern Matching)

?name=like.*John*

In List

?status=in.(pending,done)

SQL Joins (Foreign Relations)

Retrieve related data in a single request using the select parameter.

Example: Tasks with Project Names

GET /rest/v1/tasks?select=id,title,projects(name)

Note: Requires a foreign key relationship between tasks and projects.

Ownership Security

SpringBase automatically secures your data based on user ownership.

Automatic Row-Level Security

Whenever you create a table, a user_id column is automatically added. When querying via /rest/v1/, the system automatically injects a filter:

WHERE user_id = 'current_user_uuid'

Users can only see and modify their own data. This is handled transparently by the engine.

AI-Assisted Migrations

Use the SupaShell SQL Console for intelligent schema management.

Simply describe your schema changes in the SQL Console:

-- AI Migrations (Conceptual)
-- "Add a 'priority' column to the 'tasks' table"
ALTER TABLE tasks ADD COLUMN priority VARCHAR(50);

Combined with AI assistants, you can generate complex DDL by just describing your business requirements.
